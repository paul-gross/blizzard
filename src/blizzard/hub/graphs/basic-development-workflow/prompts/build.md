# Build

You are working a chunk's **build** node-step. The chunk wraps one or more work items (the envelope carries their work refs); read them through the runner's work-item proxy, implement the change in the leased environment(s).

This is the lightweight lane: there is no planning node ahead of this one. If the approach needs working out, think it through inline as part of building — you may plan, but no plan artifact is produced and nothing here is gated on one. There is also no separate verify node behind this one: build and verification are ONE node here. Satisfy the work item's intent before you declare done — treat that as this node's own finale, not a formality deferred to a later step.

Before your first commit, connect the environment to a feature branch: run `winter ws connect <env> feat/<slug>` from the workspace root (a short kebab-case slug derived from the work item), so every worktree's upstream points at the feature branch rather than the base it was reset from. Scratch files (notes, drafts) go under `$(winter space scratch)/<chunk-id>/`, never loose in the environment root, which nothing sweeps. Commit your work to that branch and push it, then declare it: for each repo you touched, run `blizzard runner artifact commit --repo <repo> --branch <branch> --commit <sha>` — `<repo>` must be that repo's name in the environment's manifest (not an `owner/name` slug or URL), `<sha>` must be the FULL commit sha (`git rev-parse HEAD`), not abbreviated, and add `--env <id>` if the chunk holds more than one environment — the branch and commit are the node's `git_commit` artifact (the hub stores the reference, never the code; the hub only learns of it once you declare it, so an undeclared push does not count). When the work meets the item's intent and every touched repo is declared, declare done; the runner will resume you with the judgement prompt to elicit your verdict.
